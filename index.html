    MailShield AI - Project Defense & Architecture Guide

    MailShield AI is a modular, defense-in-depth Email Security Gateway that analyzes inbound emails across multiple attack vectors: content semantics, sender authenticity, deceptive hyperlinks, and malicious attachment payloads.

    Multi-Layered Security Pipeline
    1. MIME Ingestion & Header Parser: Deconstructs RFC 822 email packages into headers, body parts (HTML/text), and attachments.
    2. Authentication & Spoofing Engine: Evaluates SPF, DKIM, and DMARC alignments, detects display-name impersonation, and calculates Levenshtein distance against known brand domains for typosquatting.
    3. NLP & Machine Learning Phishing Classifier: Tokenizes email body and subject using TF-IDF (Sublinear term frequency, 1-2 n-grams) and applies a balanced Logistic Regression classifier with Explainable AI (XAI) feature attribution.
    4. Link & URL Audit: Extracts HTML anchor tags and plain URLs, detects mismatched anchor texts, IP address hostnames, deceptive subdomains, and high-risk TLDs.
    5. Attachment Sandbox: Detects double-extension exploits (e.g. .pdf.exe), macro-enabled documents (.docm), computes SHA-256 digests, and matches against threat intelligence lists.
    6. Cryptographic Suite: Provides end-to-end privacy and integrity via Hybrid AES-256-GCM + RSA-2048 encryption and RSA-PSS digital signatures.
    Core Mathematical & Cryptographic Models
    • TF-IDF (Term Frequency-Inverse Document Frequency): Weights rare, high-information security urgency terms higher than common stop words.
    • Levenshtein Edit Distance: Measures minimum single-character edits (insertions, deletions, substitutions) to identify lookalike brand domains (e.g., paypa1.com vs paypal.com).
    • Hybrid Cryptography: Combines asymmetric RSA-2048 for key exchange with symmetric AES-256-GCM for authenticated stream encryption.
    Viva / Presentation Q&A

    SPF verifies sender IP against DNS records. DKIM provides a cryptographic digital signature on the email header/body. DMARC enforces domain alignment between From and SPF/DKIM, specifying whether failing emails should be quarantined or rejected.

    Attackers set their display name to a trusted brand (e.g., "PayPal Support"), while the actual underlying email address is a completely unrelated external mailbox (e.g., attacker@xyz.com). MailShield AI detects when the display name claims a brand identity that the sender domain does not belong to.

    RSA asymmetric encryption is computationally slow and can only encrypt data smaller than its key size (e.g., ~214 bytes for RSA-2048 with OAEP). Hybrid encryption uses blazing-fast AES-256-GCM for arbitrary-sized emails and attachments, and only encrypts the 32-byte AES key with RSA.

    Windows hides known extensions by default. An attacker names a file Report.pdf.exe. The user sees Report.pdf with a document icon, double-clicks it, and unknowingly executes malicious binary code. MailShield AI analyzes all extension segments to catch this.
